# ExpenseTracker API

A lightweight personal-finance Web API built with ASP.NET Core (.NET 8) and Entity Framework Core. It provides secure authentication (JWT + refresh tokens), domain-driven organization, and CRUD support for accounts, categories, incomes, expenses, savings, and future expenses.

The API is designed to be consumed by a React frontend and exposes interactive documentation via Swagger in Development.

## Quick overview

- Target framework: .NET 8, C# 12
- Architecture: Layered (API / Application / Domain / Infrastructure)
- Authentication: ASP.NET Core Identity with JWT access tokens and secure refresh tokens ([Read more](#authentication--refresh-tokens))
- Persistence: Entity Framework Core (SQL Server by default)
- Migrations: `ExpenseTracker.Infrastructure/Migrations`
- API docs: Swagger UI enabled in Development via `AddCustomSwagger()` / `UseCustomSwagger(...)`  
- CORS:Dedicated policy for React frontend (`ReactCors`)

## Configuration

Primary configuration lives in `ExpenseTracker.API/appsettings.json`, but the secret values are left
blank in every tracked file — they're supplied via user-secrets (dev) or environment variables
(docker/production). Important keys:

- `ConnectionStrings:PostgreSQL` — Npgsql connection string (active provider)
- `ConnectionStrings:MongoDbConnection` — MongoDB Atlas connection string (UserPreferences only)
- `Jwt:Key` — Signing key, **must be ≥ 32 bytes** — the app throws at startup otherwise
- `Jwt:Issuer`, `Jwt:Audience` — Token issuer and audience
- `RefreshToken:Pepper` (optional) — Server-side pepper for refresh token hashing
- `RefreshToken:Longevity` — Refresh token longevity (days)

### Secrets

Never put real values in `appsettings*.json`, `appsettings.Migrations.json`, or `docker-compose.yml` —
those files are tracked in git. Instead:

**Development (`ExpenseTracker.API`, has `UserSecretsId` already configured):**
```bash
dotnet user-secrets set "ConnectionStrings:PostgreSQL" "Host=localhost;Port=5432;Database=ExpenseTracker;Username=alp;Password=<...>;"
dotnet user-secrets set "ConnectionStrings:MongoDbConnection" "mongodb+srv://<user>:<pass>@expensetrackercluster.d9r0itm.mongodb.net/?appName=ExpenseTrackerCluster"
dotnet user-secrets set "Jwt:Key" "<openssl rand -base64 48>"
dotnet user-secrets set "RefreshToken:Pepper" "<openssl rand -base64 48>"
```

**EF Core migrations / design-time factories** (`ExpenseTracker.Infrastructure/Persistence/Factories`)
read `appsettings.Migrations.json` first, which is tracked with an empty `PostgreSQL` value. Override it
with an environment variable instead of editing the file:
```bash
$env:ET_MIGRATIONS_CONNECTIONSTRING = "Host=localhost;Port=5432;Database=ExpenseTracker;Username=alp;Password=<...>;"
dotnet ef database update --project ExpenseTracker.Infrastructure
```

**Docker Compose:** `docker-compose.yml` reads `Jwt__Key` from `${JWT_KEY}`, sourced from a local `.env`
file (gitignored — see `.env.example` for the expected keys). Compose loads `.env` automatically:
```bash
cp .env.example .env
# edit .env and set JWT_KEY
docker compose up
```

If `Jwt:Key` is missing or under 32 bytes from any source, the API throws a clear exception at startup
instead of silently skipping JWT validation.

## Run locally

Using **Visual Studio 2026**:

1. Open the solution 
2. Set `ExpenseTracker.API` as the **Startup Project**.  
2. Choose a launch profile (for example, __Kestrel__ or __IIS Express__).  
3. Add connection string and JWT secrets to `appsettings.json` or __dotnet user-secrets__.  
4. Apply migrations 
5. Run the project.

#### Using **PMC**
```bash
Update-Database -Context ApplicationDbContext
```
or if that doesn't work **.NET CLI**
```bash
dotnet ef database update --project ExpenseTracker.Infrastructure
```

### Restore and Build
```bash
dotnet restore
dotnet build
dotnet run --project ExpenseTracker.API
```

And run the app, After startup, Swagger is available in Development at `https://localhost:{port}/swagger`.

## Authentication & refresh tokens

- Access tokens: 
    - JWT signed with `Jwt:Key`.
    - Short-lived, sent via `Authorization: Bearer <token>` 
- Refresh tokens: 
    - Generated by `TokenUtil.GenerateRefreshToken` 
    - Sent to client as an **HttpOnly, Secure cookie**.
    - Only the **hashed token** is stored in the database.
    - Optional **server-side pepper** can be applied before hashing.

This design prevents token theft and ensures long-lived sessions without exposing anything.

## Currencies & conversion

Each user maintains their own currencies (Currency CRUD) and picks a base currency in
user preferences (`BaseCurrency`, default `EUR`). `Currency.ExchangeRateToBase` is a
manually maintained multiplier whose direction is fixed everywhere in the codebase:

```
amountInBase = amount * ExchangeRateToBase
```

i.e. the rate converts one unit of *that* currency into the user's base currency; the
base currency itself should have rate 1. Reports and category summaries return
per-currency `subtotals` plus a `convertedTotal` in the base currency; when the base
currency is unset or any involved currency has no usable rate, `convertedTotal` is
`null` and `hasMissingRates` is `true` — clients must show subtotals instead of a
single number in that case.

# Frontend (React)

This repository contains only the backend API. As this is supposed to be a full-stack Expense Tracker application. The frontend is maintaned in a different repository:

Repository: https://github.com/Alp-Balaj/expense-tracker-front
> Refer to the frontend repository's README for setup instructions, environment variables, and so on...

The frontend is responsible for:
- User authentication and session handling
- Entity and reporting UI
- Communicating with this API via HTTPS (JWT + refresh tokens)

To run the full application locally, clone both repositories, start the API first, then run the React frontend and point it to the API base URL.
